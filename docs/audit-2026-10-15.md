# 初版の操作性監査（2026-10-15）

対象：v1.0.0 / b1ca7f0。既存の明るい実験ノート風のデザインを維持して検査した。以下は修正前の記録。スコアはプロジェクト内の目安であり、WCAG適合認証ではない。

## デザイン上のアンチパターン

合格。暖色の紙面、罫線、大きな3D表示、控えめな朱色のアクセントが一貫している。グラデーション文字、過剰なカードの入れ子、装飾のためのアニメーションはない。

| 評価軸 | 点数 / 4 | 根拠 |
| --- | --- | --- |
| アクセシビリティ | 2 | フォーカス消失と小さな説明文字のコントラスト不足 |
| 性能 | 3 | 変更時のみ3Dを描画。Three.jsの約567kBチャンクは既知の制約 |
| レスポンシブ | 2 | 狭い画面に対応するが、入力・補助ボタンの操作領域が小さい |
| テーマ | 3 | 選択された明るいテーマは一貫。色の一部は直接指定 |
| アンチパターン | 4 | 用途に合った構成、不要な装飾なし |
| 合計 | **14 / 20** | 改善する箇所が明確な状態 |

## 検出事項

### P1：再描画でキーボードフォーカスが失われる

- 場所：`src/main.ts`の`renderControls`、`action`、補間プリセットの`onchange`。
- 分類：アクセシビリティ。
- 再現：q↔−qボタンにフォーカスしEnter。ボタンの押下状態は変わるがフォーカスが外れ、続けてEnterで戻せない。補間例の選択でも同様。
- 影響：連続したキーボード操作が中断する。フォーカス順序（WCAG 2.4.3）に関係する。
- 対応：再描画前の操作対象を識別し、置換後の同じコントロールにフォーカスを戻す。`/harden` → `/polish`。

### P1：小数を1文字ずつ入力できない

- 場所：`src/main.ts`の`bindSliders`。
- 分類：入力の操作性。
- 再現：Eの移動Xを空にして`0.5`を1文字ずつ入力すると`2`になる。`0.`の段階で入力文字列が`0`に置換され、次の5が別の数値として解釈される。
- 影響：平行移動や補間率の直接入力が正しくできない。貼り付けでは検出できない。
- 対応：編集中の文字列を保持し、有限かつ範囲内の値だけ計算へ反映。確定時に範囲・刻みを整える。`/harden` → `/polish`。

### P1：操作説明の文字が4.5:1未満

- 場所：`src/style.css`の`.drag-hint`。
- 分類：アクセシビリティ。
- 測定：文字`#68766b`と背景`#f0f0e8`の比は約4.17:1。
- 影響：小さな通常文字に必要なWCAG 1.4.3の4.5:1を満たさない。
- 対応：既存の濃い補助テキスト色へ変更。`/normalize` → `/polish`。

### P2：スマートフォンで操作領域が小さい

- 場所：`src/style.css`の数値入力、range、`.presets button`、`.quiet`、`.checkbox`。
- 分類：レスポンシブ。
- 測定：390px幅でrangeは20px、数値欄は28px、補助ボタンは36px高。
- 影響：タッチで狙いにくい。44pxは今回採用する操作性の目標であり、WCAG AAの一律の最小値だと主張するものではない。
- 対応：モバイルではラベルを含む操作領域を44px以上にする。`/adapt` → `/polish`。

## 共通原因と維持する点

入力中のDOMを作り直す処理と、入力値を毎文字正規化する処理が、キーボード利用の継続性を壊していた。数学テストだけでは発見できないため、実ブラウザでの入力列とフォーカスをテストする。

軸の文字ラベル、数値欄、停止可能な再生、デモ切替時のGPUリソース解放、独立した数学コアと既知解の検証は維持する。単一の明るいテーマはユーザーの選択であり、ダークモード未対応を問題とは扱わない。

## 対応結果

P1の3件、P2の1件を修正した。フォーカス消失、小数入力、タッチ領域、コントラストはそれぞれ修正前に実ブラウザテストが失敗し、修正後に成功した。

- 入力中の文字列を保持し、範囲外・刻み違いの値は確定時に補正する。
- 操作パネル再描画後に元のコントロールへフォーカスを戻す。
- モバイルの操作領域は44px以上。数値欄と選択欄は16px文字にする。
- ドラッグ説明に専用の濃いテキスト色を使用する。
- 9つのChromiumテストをCIへ追加し、失敗時のスクリーンショットとトレースを7日間保存する。

再評価は **17 / 20**（アクセシビリティ3、性能3、レスポンシブ4、テーマ3、アンチパターン4）。今回の検査範囲で検出したP1・P2は解消した。すべての支援技術・実機端末を網羅した評価ではなく、WCAG全体への適合は主張しない。Three.jsのチャンクサイズと色トークンの拡張余地は引き続き既知の制約として残る。
